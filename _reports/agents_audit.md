Пользователь спросил: «все ли проекты у нас комитятся, чтобы не потерять ничего при форс-мажоре». Проверка показала, что **автокоммит был сломан ~22 часа** — от 2026-08-04 23:27 до момента проверки. Причины и статус:

1. **Завис `.git/index.lock`** (создан 2026-08-04 22:21 МСК, скорее всего из-за прерывания скрипта сном/выключением) — каждый следующий запуск падал с `ADD FAILED rc=128`. **Устранено** — лок перенесён в `tech/_stale_locks/`.
2. **Три битых symlink'а** (`ai-clone/`, `business/`, `.claude/skills/notebooklm/`) стали нечитаемыми и блокировали `git add -A` **целиком** — то есть ни один файл во всём проекте не сохранялся в git, пока не устранена хотя бы одна из трёх поломок. Реальный контент цел (проверено по идентичным git-хэшам блобов в `projects/second-brain/ai-clone`, `projects/second-brain/business`, `.agents/skills/notebooklm`). **Устранено** — устаревшие записи убраны из индекса (`git rm --cached`), пути добавлены в `.gitignore`, чтобы поломка symlink'а больше не могла заблокировать весь бэкап разом.
3. `git add -A` теперь отрабатывает чисто, 475 файлов накопленных изменений стоят в индексе, готовы к коммиту. Коммит и `git push` оставлены на следующий плановый запуск `tech/auto-commit.ps1` (~2 часа) по решению пользователя — блокеров для него больше нет.

**Не устранено, требует ручных действий на Windows:**
- 2 файла книг с превышающими лимит именами (`Книги/Психология/Кинг Патрик...pdf`, `Книги/Развитие/Найду Ума...pdf`) — git не может их отследить («File name too long»), нужно переименовать короче.
- **`tech/llm-council`** — отдельный git-репозиторий, remote указывает на `github.com/karpathy/llm-council` (чужой репозиторий, не пользователя). При этом там 10+ изменённых файлов (config.py, council.py, main.py и др.) — реальная кастомизация без какого-либо бэкапа. Решение пользователя: сделать приватный форк на GitHub и переключить remote (см. чат за 2026-08-05).
- Крупные бинарники по-прежнему намеренно исключены из git (`chroma_db/`, `booklm_chunks.pkl`, книги в 3 местах, медиа «Мафии») — `D:\SAVE\C_Backup` их не покрывает (тот бэкап — только профиль Windows на диске C:, не `D:\AI_Project`). Отдельная стратегия бэкапа для них ещё не выбрана.
