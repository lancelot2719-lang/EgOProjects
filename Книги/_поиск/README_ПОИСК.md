# Поисковая система по библиотеке книг

## Что это

Полнотекстовый поиск по вашей библиотеке: **246 книг, 83,5 млн символов,
45 400 фрагментов, 15 тем**. Позволяет задать вопрос обычным языком и
получить релевантные отрывки с указанием книги и темы.

## Файлы

| Файл | Назначение |
|---|---|
| `extract.py` | Извлечение текста из книг (PDF/FB2/EPUB/TXT/ZIP) |
| `build_index.py` | Построение поискового индекса из извлечённых текстов |
| `search.py` | Собственно поиск |
| `extracted/` | Извлечённые тексты всех книг (`.txt`, по темам) |
| `index/index.pkl` | Поисковый индекс (создаётся `build_index.py`) |
| `index/stats.json` | Список проиндексированных книг и тем |

## Как запустить у себя

Нужен Python 3 и две библиотеки:

```bash
pip install scikit-learn numpy
```

Распаковать тексты и построить индекс (около 2 минут):

```bash
cat knigi_texts.tar.gz.part* > knigi_texts.tar.gz
tar xzf knigi_texts.tar.gz
python3 build_index.py
```

Искать:

```bash
python3 search.py "как формировать полезные привычки"
python3 search.py "запас прочности" --topic Финансы --top 10
python3 search.py "прокрастинация" --book "Атомные" --full
```

Параметры: `--top N` — сколько фрагментов, `--topic` — ограничить темой,
`--book` — ограничить книгой, `--full` — печатать фрагмент целиком.

## Как это устроено

Тексты режутся на фрагменты примерно по 2000 символов по границам абзацев,
дальше строится TF-IDF индекс. Ключевая деталь для русского языка: слова
обрезаются до первых 6 символов («инвестор», «инвестора», «инвестору» →
«инвест»). Это снимает падежи и числа без словаря и внешних зависимостей,
а индекс получается примерно в 5 раз компактнее, чем на символьных
н-граммах (256 МБ против 1,2 ГБ при том же качестве поиска).

## Технические решения и ограничения

**Почему не нейросетевые эмбеддинги.** Изначально планировался семантический
поиск на multilingual-эмбеддингах + FAISS. В облачной песочнице, где шла
обработка, нет доступа в интернет (`pip`, `apt`, `npm`, GitHub — всё
блокируется), поэтому установить `sentence-transformers` и `faiss` было
невозможно. TF-IDF с псевдо-основами — рабочая замена, которая ищет по
ключевым словам и их формам, но не понимает синонимы. Если захотите
семантику — у вас локально уже стоят Ollama и LM Studio, можно построить
эмбеддинги на своей машине из тех же файлов `extracted/`.

**Извлечение текста.** Главный движок — `pdftotext` (poppler). Он оказался
кардинально быстрее и надёжнее python-библиотек: файлы, на которых `pypdf` и
`pdfplumber` зависали больше 25 секунд, он читает за 1–4 секунды. `pypdf` и
`pdfplumber` оставлены запасными вариантами. Каждый PDF обрабатывается в
отдельном процессе с жёстким таймаутом, поэтому один битый файл не может
подвесить весь прогон.

**OCR не понадобился.** Ожидалось, что сканы (Ялом «Экзистенциальная
психотерапия», Бек «КПТ расстройств личности») потребуют OCR. `pdftotext`
извлёк из них полноценный текст — 1,43 млн и 1,07 млн символов
соответственно. Русский языковой пакет Tesseract в песочницу скачать не
удалось, но он и не потребовался.
