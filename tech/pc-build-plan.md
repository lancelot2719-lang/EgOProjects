# План сборки ПК под локальные LLM (финальное решение, август 2026)

## Итог

**Вариант A: RTX 5060 Ti 16GB + 64 GB RAM (~40 000 ₽).** Выбран как окончательный.

- GPU: RTX 5060 Ti 16 GB — **новый** (~40 000 ₽)
- RAM: 64 GB — уже куплена/есть (0 ₽)
- Итого: ~40 000 ₽

## Почему так

| Критерий | Вариант A (выбран) | Вариант B (отклонён) |
|---|---|---|
| Состав | 5060 Ti 16GB + 64GB | RTX 3060 12GB + 128GB RAM |
| Стоимость | ~40 000 ₽ | ~20 000 ₽ |
| 30.5B Q3 (15GB) | **30-35 ток/с** (целиком в VRAM) | ~15-18 ток/с (offload) |
| 30.5B Q4 (18GB) | ~20-25 ток/с (16+2 offload) | ~10-12 ток/с |
| 70B Q2 (27GB) | ~6-8 ток/с | ~4-5 ток/с |
| 128 GB RAM под гигантов | нет | да (модель целиком в RAM) |

Ключевые аргументы:

1. **RTX 3060 12GB — деградация**: почти равна текущей RX 6700 XT (192-bit, 360-384 GB/s) → прироста для LLM почти нет.
2. **128 GB RAM без сильной GPU — переплата**: LLM — GPU-задача, RAM включается только при offload.
3. **5060 Ti даёт 3-4× ускорение** vs текущая карта: CUDA + тензорные ядра против ROCm без тензорных ядер.
4. **64 GB RAM достаточно**: qwen3-coder Q4 (18GB) влезает с запасом, 70B Q2 работает через offload.

## Разметка дисков (финальное решение, август 2026)

Три физических диска: SSD 2TB PCIe5 (новый), SSD 250GB PCIe4 (новый), HDD 1TB (текущий D:, остаётся как есть, физически не меняется).

| Диск | Буква | Раздел | Роль |
|---|---|---|---|
| SSD 2TB PCIe5 | C: | один раздел, без дробления | Windows, программы, игры (Steam-библиотека), `C:\AI\Ollama` (модели через `OLLAMA_MODELS`), `C:\AI\HuggingFace` (кэш через `HF_HOME`/`HF_HUB_CACHE`), `C:\AI\Projects` (перенесённый D:\AI_Project) |
| SSD 250GB PCIe4 | D: | scratch/cache | `D:\Temp`, `D:\Scratch`, `D:\Docker` (Docker Desktop disk image), `D:\WhisperTemp`, `D:\Cache` (pip/npm) — только одноразовое/регенерируемое |
| HDD 1TB | E: | архив + бэкап | `E:\Archive` (Книги и холодное хранение), `E:\Backup\AI_Project` (регулярный robocopy-mirror `C:\AI\Projects`, см. `tech/backup-ai-work.ps1`) |

### Почему так, а не разбивать 2TB / не ставить Windows на 250GB

- Разбиение 2TB на партиции не даёт защиты сверх того, что даёт бэкап по папкам (robocopy бэкапит `C:\AI\Projects` независимо от того, что лежит в `C:\Games`) — зато создаёт риск упереться в границу раздела, когда игры или AI-данные вырастут неравномерно.
- 250GB под голую систему уже показал себя тесным на практике: прежний C: (112 ГБ) был забит почти до нуля без единого AI-проекта — только Windows/AppData/программы (vm_bundles Claude Desktop 10.8 ГБ, WinSxS 10 ГБ, кэши npm/pip и т.д.).
- Ollama/HF-модели — не «мусор для scratch», а дорогие в перекачке рабочие данные → остаются на 2TB через официальные переменные окружения (`OLLAMA_MODELS`, `HF_HOME`, `HF_HUB_CACHE`), а не на 250GB.
- Pagefile — System Managed на C: (2TB), ручной перенос не нужен при 64-128 ГБ RAM.
- Docker Desktop disk image, TEMP/TMP, Whisper-временные файлы — на 250GB (официально поддерживаемый перенос, безопасно терять).

### Сценарии отказа

- Слетела Windows → 2TB физически не тронут при переустановке (тот же принцип, что уже сработал с текущим D: HDD при переустановке на новый SSD).
- Умер физически 2TB SSD → git+GitHub и `E:\Backup\AI_Project` на HDD спасают рабочие данные; игры теряются (принято как некритичное).
- Умер 250GB scratch-диск → ничего не теряется, там изначально нет ничего ценного; при будущей замене на диск большего размера миграция данных не нужна.

### Что делать, когда на 2TB начнёт заканчиваться место

Не удалять рабочие файлы вручную наугад — они уже задублированы (git+GitHub и `E:\Backup\AI_Project`), поэтому риска для них нет в принципе. Порядок действий:

1. **Storage Sense** (Параметры → Система → Память) — включить автоочистку временных файлов и корзины по расписанию, закрывает большую часть роста «сам по себе».
2. **Игры — главный клапан давления.** Steam поддерживает несколько библиотек на разных дисках: при нехватке места докупить ещё один диск, добавить как вторую Steam-библиотеку, перенести крупные игры штатной функцией «Переместить папку установки». Без переустановки системы, без риска для Windows или рабочих данных, ~10 минут.
3. Только если после этого всё ещё тесно — разбирать вручную (старые проекты в архив на HDD, неиспользуемые программы).
