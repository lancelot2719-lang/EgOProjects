# Система разбора книг с ИИ: полная инструкция (v1, август 2026)

## 1. Цель

Автоматизированный разбор книг уровня NotebookLM (структура, ключевые идеи, дословные цитаты, практические действия, критика, связи с другими книгами) с **проверкой точности** и верификацией второй моделью. Всё локально/офлайн, кроме опционального судьи Claude.

## 4. Пайплайн разбора (skill `book-analysis`)

Путь: `.agents/skills/book-analysis/` — SKILL.md + scripts/pipeline.py + scripts/check_quotes.py + 8 промптов (`промпты/УРОВЕНЬ-*.txt`).

Запуск:
```powershell
python ".agents/skills/book-analysis/scripts/pipeline.py" "<книга.txt>" `
  --author "Автор" --title "Название" --rag-source "имя_файла_в_RAG.txt"`
  # --no-claude  # если не нужен судья Claude
```

Результаты: `Книги/_Разборы/новые_разборы/<книга>_МАКСИМАЛЬНЫЙ.md` + `_ВЕРИФИКАЦИЯ.md`. Промежуточные шаги: `temp/book_pipeline/` (checkpoint'ы — повторный запуск пропускает готовые шаги).

**Шаги (~12 мин на книгу):**
1. **Digest**: выжимка HEAD 25K + 12 срезов × 3K + TAIL 8K ≈ 69 КБ ≈ 28K токенов (покрытие ~7% толстой книги; для Смита это 69 КБ из 2.3 МБ символов)
2. **B1/B2/B3 параллельно** (threads, ctx=32768): структура / 12-14 идей / 8-10 дословных цитат с позициями [начало]/[срез N%]/[конец]
3. **D**: 8 RAG-вопросов × 2 фрагмента × 1200 символов из chroma_db (фильтр `source_file`)
4. **RAG-проверка идей**: каждая идея B2 → эмбеддинг → топ-1 фрагмент → ПОДТВЕРЖДЕНО/СЛАБО
5. **B4-сборка**: единый разбор (идеи + цитаты + действия + критика + связи), RAG-контекст как доп. источник
6. **Автопроверка цитат + чисел** (`check_quotes.py`): детерминированный fuzzy-поиск по полному тексту — [OK] дословно / [OK*] с пропуском / [НЕТ], плюс поиск всех чисел из разбора (годы, суммы, %)
7. **C-верификация**: судья Claude Opus 5 (если ключ) или qwen3.5 при ctx=32768 — таблицы «цитаты/факты/идеи» + вердикт

## 5. Критичные знания (выстраданы)

1. **`"think": false` обязателен** для qwen3.5: при включённом thinking-режиме и ctx=16384 модель сжигает весь контекст на скрытые размышления (`done_reason: length`, пустой response). С флагом B1 ускорился с 9 мин до 0.2 мин.
2. **ctx**: B-шаги 16384, судья C — 32768 (ему нужен весь digest + разбор).
3. **keep_alive: "30m"** — модель не выгружается между шагами (экономия десятков секунд на каждом).
4. **KV-кэш**: при 12 GB VRAM + 16 GB RAM держим только qwen3.5; mistral — слабый судья (отвечает на англ., вне формата). qwen3-coder (18 ГБ) — не влезает.
5. **Ollama не любит одновременные запросы** — пайплайн сериализует через threading.Lock (параллельность выигрыша по времени не дала, но архитектура готова под многопоточность).
6. **Автопроверка цитат надёжнее судьи**: qwen3.5-судья ошибочно пометил 2 дословные цитаты «ОШИБКА»; скрипт доказал, что они дословные. Скрипт — источник истины по дословности.
7. **Ловушки промптов**: судья приписывает автору «связи с другими книгами» (Хайек/Милль у Смита) как факт — в разборе такие связи помечаются как «внешняя интерпретация».

## 9. Ограничения и известные проблемы

1. qwen3.5-судья иногда ошибается (ложные «ОШИБКА» по цитатам) — нужен Claude Opus 5 как судья
2. 16 GB RAM — потолок: нет параллельной работы нескольких LLM-процессов, Open WebUI + Ollama + браузер уже напрягают
3. Рекомендация апгрейда: 32 GB RAM даст модели 14B, больший KV-кэш, параллельность; скорость prefill всё равно упрётся в 12 GB VRAM
4. digest для книг > 2 МБ символов (~300K+ слов) может терять нюансы (нет иерархической суммаризации)
5. npx-кэш MCP-сервера — подставлял старую версию (фикс: прямой путь к .cmd)
