# Перенос истории чатов OpenCode → Cloude (Claude Code), с разбивкой по проектам

## Контекст

Пользователь вёл переписку с ИИ в OpenCode. Все данные хранятся в одной базе
SQLite `C:\Users\x2\.local\share\opencode\opencode.db` (~2.9 ГБ): 56 сессий,
4507 сообщений, 17882 "частей" (текст + вызовы инструментов).

Проблема: OpenCode почти не различал подпроекты — он писал в поле
`session.directory` рабочую папку процесса, а не конкретный подпроект:

- **45 сессий** → `D:/AI_Project` (корень целиком, а не `tech/`,
  `projects/second-brain/` и т.д.)
- **10 сессий** → `C:/Users/x2/Documents/New OpenCode Project` (вообще вне
  D:\AI_Project)
- **1 сессия** → `D:/AI_Project/Obsidian/EgO Info`

Цель — импортировать переписку в Cloude (Claude Code) так, чтобы каждый
реальный проект показывал свою историю отдельно. Claude Code хранит историю
как `C:\Users\x2\.claude\projects\<encoded-path>\<sessionId>.jsonl`, где
`<encoded-path>` — абсолютный путь проекта с заменой `\`, `:`, пробела на `-`
(подтверждено: `D:\AI_Project\Cloude` → `D--AI-Project-Cloude`). Список
проектов также должен быть зарегистрирован в `C:\Users\x2\.claude.json`
(ключ `projects`, реальный путь как ключ).

Решено с пользователем:
1. Список всех 56 сессий (включая 10 "внешних") показать для ручного разбора
   — пользователь сам укажет, в какую папку под D:\AI_Project отнести
   каждую сессию (в т.ч. переносит 10 внешних сессий внутрь D:\AI_Project).
2. Переносить только текст переписки (user/assistant), без содержимого
   вызовов инструментов — компактно и достаточно для чтения истории.

Все новые проекты Cloude тоже будут жить на D:\AI_Project (диск C почти
заполнен) — при регистрации в `.claude.json` пути должны указывать на D:.

## Подход — два шага

### Шаг 1. Сгенерировать манифест для ручной разметки

Скрипт на Python (`sqlite3` встроен, копировать 2.9 ГБ файл не нужно —
открывать `opencode.db` в режиме read-only через `sqlite3.connect("file:...?mode=ro", uri=True)`,
это безопасно даже если OpenCode запущен параллельно).

Для каждой из 56 сессий вытащить: `session.id`, `directory`, `title`,
`time_created` (перевести из ms в дату), и превью — первые ~200 символов
первого сообщения с `role=user` (текстовые part'ы, `data->>'text'`).

Результат — читаемый Markdown-файл с таблицей:

```
| # | Дата | Исходная папка (OpenCode) | Заголовок | Превью | Целевая папка (заполнить) |
```

Колонку "Целевая папка" оставить пустой (или с предзаполненной догадкой —
например, если превью явно упоминает "second-brain" или "vpn"/"xray" и т.п.
можно подставить вероятную папку как подсказку, но без автоматического
решения).

Сохранить в `D:\AI_Project\tech\opencode-migration\sessions-manifest.md`
(по правилу файловой сортировки из AGENTS.md — технические файлы в `tech/`).

Показать файл пользователю, дождаться, пока он заполнит колонку "Целевая
папка" для всех 56 строк (правит файл сам или диктует в чат).

### Шаг 2. Импорт по размеченному манифесту

Второй скрипт читает заполненный `sessions-manifest.md` (или CSV, если так
удобнее пользователю) и для каждой сессии:

1. Берёт `session_id → target_folder` из манифеста.
2. Из `opencode.db` вытягивает все сообщения сессии по порядку
   (`message` join `part`, сортировка по `time_created`), берёт только
   `part.data->>'type' == 'text'` (пропускает tool-call/tool-result части).
3. Строит JSONL в формате Claude Code: по одной строке на сообщение,
   поля `type` (`user`/`assistant`), `message: {role, content:[{type:"text",text}]}`,
   `uuid` (новый), `parentUuid` (цепочка внутри сессии), `timestamp` (ISO 8601
   из `time_created`), `sessionId` (новый UUID), `cwd` = целевой абсолютный
   путь, `version`, `gitBranch:""`.
4. Кодирует целевой путь по схеме Claude Code (`\`, `:`, пробел → `-`),
   создаёт (если нет) `C:\Users\x2\.claude\projects\<encoded>\` и пишет туда
   `<new-sessionId>.jsonl`.
5. Если целевого пути ещё нет в `C:\Users\x2\.claude.json` → `projects`,
   добавляет минимальную запись (реальный путь как ключ, пустые
   `allowedTools`/`mcpContextUris`, `hasTrustDialogAccepted:false`), чтобы
   проект появился в списке проектов Cloude.

**Перед записью** — сделать бэкап `C:\Users\x2\.claude\projects\` (только
новых/затрагиваемых подпапок не будет — операция аддитивная, но на всякий
случай скопировать `.claude.json` в `.claude.json.bak-<timestamp>` перед
правкой, т.к. это общий файл).

## Обнаруженное расхождение (после отчёта "готово")

Пользователь сообщил, что перенос уже выполнен (58 сессий, 10
зарегистрированных проектов, CLAUDE.md для каждой папки, временные скрипты
удалены). Проверка файловой системы это не подтверждает:

- В `C:\Users\x2\.claude\projects\` появились только 2 новые папки:
  `D--AI_Project` (47 jsonl) и `D--AI_Project-Obsidian-EgO-Info` (1 jsonl).
  Папок `tech`, `health`, `finance`, `notes`, `sales`, `business`, `projects`
  НЕТ — то есть разбивки по проектам не произошло, почти всё свалено в один
  "корневой" проект.
- Кодировка пути неверна: реальная схема Claude Code заменяет на `-`
  **любой** не-буквенно-цифровой символ, включая `_` (подтверждено:
  `D:\AI_Project\Cloude` → `D--AI-Project-Cloude`, дефис вместо `_`). Новые
  папки используют `D--AI_Project` (подчёркивание сохранено) — это не
  совпадает со схемой, поэтому Cloude может не связать эти сессии с реальной
  рабочей папкой `D:\AI_Project`.
- В `C:\Users\x2\.claude.json` ключа `projects` для `tech`, `health`,
  `finance`, `notes`, `sales`, `business`, `projects` — нет. Есть только
  `D:\AI_Project\Cloude` (существовал ещё до этой задачи).
- `D:\AI_Project\tech\opencode-migration\export_manifest.py` и
  `sessions-manifest.md` всё ещё на месте — не удалены, как было заявлено.

Вывод: реальный результат на диске не соответствует присланному отчёту.
Нужно уточнить у пользователя, откуда взялся отчёт (другой инструмент/сессия?)
и как поступить с уже созданными (неверно закодированными) файлами
`D--AI_Project` и `D--AI_Project-Obsidian-EgO-Info` — использовать как основу,
исправить кодировку, или удалить и сделать перенос заново по шагу 2
исходного плана (используя уже готовый `sessions-manifest.md`).

## Пилот подтверждён

Сессия "Подбор оптимальных тренировок" (`ses_0ae2b413cffeETOBVviWlJDc2l`)
успешно перенесена через `D:\AI_Project\tech\opencode-migration\import_one.py`
в `C:\Users\x2\.claude\projects\D--AI-Project-----------\` (кодировка пути
подтверждена реверсом `claude.exe`: функция `x0()` = `replace(/[^a-zA-Z0-9]/g,'-')`,
т.е. **любой** не-ASCII символ, включая кириллицу, заменяется на `-` —
кириллические папки одинаковой длины будут схлопываться в одну и ту же
закодированную папку, это ограничение самого Cloude). Пользователь
подтверждает каждый перенос лично, открывая Cloude в целевой папке.
