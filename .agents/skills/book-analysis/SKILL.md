# Анализ книг (book-analysis)

Многоэтапный пайплайн разбора книг с проверкой точности: параллельные проходы структуры/идей/цитат через Ollama, RAG-подтверждение по базе знаний, детерминированная автопроверка цитат скриптом и верификация отдельной моделью-судьёй.

## Когда использовать

- Пользователь просит «разбери книгу», «сделай разбор», «проанализируй книгу»
- Есть файл текста книги `.txt` (обычно в `Книги/тексты_для_NotebookLM/` или `projects/knigi/`)
- Нужен разбор уровня NotebookLM: структура, идеи, цитаты, действия, критика

## Быстрый запуск (один разбор, ~12 мин)

```powershell
python "D:\AI_Project\.agents\skills\book-analysis\scripts\pipeline.py" `
  "D:\AI_Project\Книги\_Разборы\тексты_для_NotebookLM\КНИГА.txt" `
  --author "Имя Автора" --title "Название книги" `
  --rag-source "имя_файла_в_RAG.txt"   # опционально: если книга уже проиндексирована в chroma_db
```

Результаты появятся в `D:\AI_Project\Книги\_Разборы\новые_разборы\`:
- `<книга>_МАКСИМАЛЬНЫЙ.md` — готовый разбор (структура, 12+ идей, цитаты, действия, критика, связи)
- `<книга>_ВЕРИФИКАЦИЯ.md` — отчёт судьи (цитаты/факты/идеи)

## Режимы

| Режим | Команда | Время |
|---|---|---|
| Максимальный (по умолчанию) | `pipeline.py книга.txt [--rag-source ...]` | ~15-20 мин |
| Без судьи Claude (только qwen3.5) | добавить `--no-claude` | то же |
| Без RAG (книга не в базе) | не передавать `--rag-source` | ~13-17 мин |

## Шаг 0: аудит очереди перед массовым прогоном

```powershell
python ".agents/skills/book-analysis/scripts/audit_books.py" "<папка_с_книгами>" [--min-chars 100000]
```
Находит дубликаты (по нормализованному названию) и файлы-саммари < 100K символов — экономит ~треть очереди.

## Что делает пайплайн (шаги)

1. **Digest** — компактная выжимка книги (HEAD 25K + 12 срезов × 3K + TAIL 8K ≈ 67-69 КБ / ~28K токенов)
2. **B1/B2/B3 ПАРАЛЛЕЛЬНО** (промпты `prompts/УРОВЕНЬ-B1..B3`, ctx=32768): структура, 12-14 идей, 8-10 дословных цитат с позициями
3. **D — RAG-ответы** (если `--rag-source`): 8 вопросов по книге, 2 фрагмента × 1200 символов из chroma_db
4. **RAG-проверка идей** — каждая идея из B2 подтверждается поиском в базе (ПОДТВЕРЖДЕНО/СЛАБО)
5. **B4 — сборка**: единый разбор по шаблону `УРОВЕНЬ-B4_агрегация.txt` (идеи + цитаты + действия + критика + связи)
6. **Автопроверка цитат И ЧИСЕЛ** — `check_quotes.py`: детерминированный fuzzy-поиск каждой цитаты по полному тексту (дословно / с пропуском / НЕ НАЙДЕНО) + поиск всех чисел разбора (годы, суммы, %)
7. **C — верификация** судьёй: Claude Opus 5 (если ключ в `D:\AI_Project\temp\.env`), иначе qwen3.5 при ctx=32768
8. **Метрики**: строка в `Книги/_Разборы/новые_разборы/metrics.csv` (книга, доля прошедших цитат, числа, идеи, время)

## Критичные настройки

- **Ollama**: модель `qwen3.5:latest` (или поменяйте `MODEL` в pipeline.py). Флаг `"think": false` обязателен — без него qwen3.5 тратит весь контекст на «размышления» и возвращает пустые ответы при ctx=16384.
- **keep_alive: "30m"** — модель не выгружается между шагами.
- **Ключ Claude** для судьи: файл `D:\AI_Project\temp\.env` с `ANTHROPIC_API_KEY=sk-ant-...` (не подписка Pro — нужен API-ключ с console.anthropic.com).
- **RAG**: chromadb по пути `D:\AI_Project\projects\knowledge-base\chroma_db`, коллекция `books`, фильтр по `source_file`; эмбеддинги `intfloat/multilingual-e5-small`. Если книги нет в базе — пропустите `--rag-source`.

## Как добавить книгу в RAG (для шага D)

Если настроен MCP-сервер Obsidian (см. opencode.json), можно после генерации записать разбор в vault-заметку (папка `Книги/` или `polka/`) через `obsidian_*` инструменты — разбор пригодится как есть, markdown-совместим.

## Известные ограничения

- Судья qwen3.5 иногда ошибочно помечает дословные цитаты «ОШИБКА» — сверяйтесь с отчётом `check_quotes.py` (он детерминирован и надёжнее).
- **Судья проверяет по digest, а не по полному тексту** — раздел 3b даёт ЛОЖНЫЕ «ОШИБКА СВЯЗИ» для имён, которые есть в книге, но не попали в выжимку (пример: Платон/Аристотель/Монтескье у Смита). Любое сомнение из 3b проверяется grep по полному тексту (RU и EN-версия: кириллица и латиница), только потом правка. [ОШИБКА СВЯЗИ] — сигнал, а не приговор.
- Для книг > 400К слов digest может потерять нюансы — идеи в B2 могут быть обобщёнными.
- Рекомендация по RAM: 16 ГБ хватает при текущем digest; 32 ГБ дадут параллельную работу и модели 14B.

## Обязательные правки после верификации (публикация)

1. Если в `_ВЕРИФИКАЦИЯ.md` есть `[ОШИБКА]` / `[ОШИБКА СВЯЗИ]` (кроме случаев, где check_quotes.py подтверждает дословность) — разбор НЕ публикуется без исправления.
2. **Checkpoint-логика**: шаги B1-B4 пропускаются, если файл в `temp/book_pipeline/` существует. При изменении промпта шаг пересобирается автоматически (сверка времени промпта vs checkpoint, метка `[stale]`). Если нужно форсировать — удалите нужный файл из `temp/book_pipeline/` (например, `b4_final.txt` для пересборки только B4+C).
3. Типовые правки:
   - **Раздел «Связь с другими книгами»**: имена/книги без прямого упоминания в тексте — либо переформулировать тематически без названий, либо пометить «внешняя интерпретация, уверенность низкая». Прямые упоминания (Платон, Аристотель и т.п.) остаются с высокой уверенностью. ВАЖНО: сначала grep по полному тексту (RU+EN), т.к. судья судит по digest и может ложно сигналить.
   - **Числа**: никаких «18+» вместо «~18» — только точное значение из текста с той же оговоркой.
   - **Факты**: перепроверять суммы/даты по полному тексту (пример: «90 млн за Испанию» оказалось «90 млн — война с Францией, 40 млн — Испания+Франция»).
4. Каждый файл разбора содержит в футере маркировку судьи (`Верификация: qwen3.5:latest` / `Claude Opus 5`) — если судья qwen, пометка предупреждает, что нужен выборочный аудит.
5. После правки — повторная сверка исправленного места по тексту книги, затем можно публиковать.
